# Matcha for iPhone

This branch (`matcha`) is Element X iOS configured as **Matcha**: bundle ID `com.matchahoneylatte.matcha`, signed by
your own team, installable on an iPhone with a **free Apple ID** ("Personal Team"). It carries the Matcha features of the
Android fork (platform plan §4, `element-x-android/MATCHA_PLATFORMS_PLAN.md`): named threads and the chip bar, task boards,
the Tasks tab, reminders, notes, the Chats · Tasks · Notes · Channels tabs and the WhatsApp-like look. §0 says where each
stands, §3.4 how to put the app on your iPhone.

Base: `element-hq/element-x-ios` develop `2f9bac8` ("Prepare next release", one commit past `release/26.10.7`, Rust SDK
26.10.24). Git LFS snapshots were not downloaded (`GIT_LFS_SKIP_SMUDGE=1`); keep it that way.

## 2. Capabilities: what a free Apple ID can sign

Source: Apple, "Supported capabilities (iOS)",
https://developer.apple.com/help/account/reference/supported-capabilities-ios (fetched 2026-10-24; the column
"Apple Developer" is a free Apple Account that accepted the Developer Agreement).

Supported for a free account: **App groups, Background modes, Data protection, HealthKit, HomeKit, Inter-App Audio,
Keychain sharing, Maps, Wireless Accessory Configuration.** Not supported (paid program only), among others: **Push
notifications, Communication Notifications, Associated domains**, Siri, Time Sensitive Notifications, iCloud, Sign in
with Apple, App Attest, Network extensions.

The NSE's `com.apple.developer.usernotifications.filtering` is not in that table at all: Apple grants it on request to
program members (https://developer.apple.com/documentation/bundleresources/entitlements/com.apple.developer.usernotifications.filtering,
"To apply for this entitlement, see notification-service").

Personal team limits, from Apple's "Developer account overview"
(https://developer.apple.com/help/account/basics/about-your-developer-account, fetched 2026-10-24): up to **10 App IDs,
which expire after 7 days**; up to **3 devices**; up to **3 apps per device**; provisioning profiles **expire 7 days**
from issuance, then you rebuild and reinstall.

### What Element X iOS asks for, and what Matcha does with it

Targets: `ElementX` (application), `NSE` (app extension, `com.apple.usernotifications.service`), `ShareExtension` (app
extension, `com.apple.share-services`). The other targets have no entitlements: `MapLibreInterface` and `MapLibreShim`
(embedded frameworks), `MatrixRustSDKMocks` (static library), five test bundles, `Periphery` (aggregate).

| ElementX | `com.apple.developer.usernotifications.communication` | no | kept | **removed** |

(`INSendMessageIntent`, `INStartCallIntent`), the URL schemes `com.matchahoneylatte.matcha` and `matrix`.

### What degrades on a personal team, and why nothing crashes

- **No push, so no notifications.** `registerForRemoteNotifications()` fails and `NotificationManager.registrationFailed`
  only logs it; no pusher is registered and the NSE never runs. Messages arrive when the app is open.
- **Communication notifications** are missing too; the NSE and the intent donation in `TimelineController` already
  wrap them in `try?` / `do-catch`.
- **App group**: signable, but `URL.appGroupContainerDirectory` (`ElementX/Sources/Other/Extensions/URL.swift:15`)
  already falls back to the app's own container when the group is unavailable, so no new code was needed.
- **Calls** are hidden in every build; with no push, VoIP pushes (`PKPushRegistry`) never arrive anyway.
- **Every 7 days** the profile expires and the app stops launching; rebuild and reinstall (§3.4). Reinstalling over the
  app with the same team and bundle ID keeps its data, so you stay signed in.
- The app uses 3 App IDs (app, `.nse`, `.shareextension`) of the 10 allowed per 7 days. Apple doesn't say whether the
  two extensions count towards "3 apps per device"; if an install fails on that limit, remove another sideloaded app.

Limits of every build, not only the personal one: no universal links (`matrix.to` links open Safari) and no sign in to
OIDC homeservers such as matrix.org, whose `https://element.io/oauth/...` redirect needs Element's associated domain.
POND's homeserver is password-only, so neither matters today.

### 3.4 Your iPhone (free Apple ID)

On the phone: connect it by cable, trust this Mac, then Settings → Privacy & Security → Developer Mode → on (restarts).

```bash
MATCHA_PERSONAL_TEAM=YES MATCHA_TEAM_ID=<team ID> xcodegen
xcrun xctrace list devices                       # the iPhone's UDID is the last value in brackets
xcodebuild -project ElementX.xcodeproj -scheme ElementX -configuration Release \
  -destination 'platform=iOS,id=<UDID>' -derivedDataPath build/DerivedData \
  -allowProvisioningUpdates -allowProvisioningDeviceRegistration build
xcrun devicectl device install app --device <UDID> build/DerivedData/Build/Products/Release-iphoneos/ElementX.app
```

`-allowProvisioningUpdates` lets Xcode register the three App IDs and the app group for your personal team and make
the 7-day profiles; `-allowProvisioningDeviceRegistration` registers the destination iPhone with the team. Build for
the iPhone itself, not `generic/platform=iOS`: a personal team's profiles only cover devices registered with it, and
you can't add one on the developer website, so with no registered device Xcode can't make a profile. Or open
`ElementX.xcodeproj`, pick the iPhone and press Run. The first launch is blocked until you trust yourself: Settings →
General → VPN & Device Management → your Apple ID → Trust.

Sign in: tap "Sign in manually", type your homeserver, Continue, then your user name and password. Repeat the build and install every 7 days; reinstalling keeps you signed in.

What this phase proved on the Mac: the app compiles for a real iPhone (`xcodebuild build -scheme ElementX -configuration
Release -destination 'generic/platform=iOS' CODE_SIGNING_ALLOWED=NO`, BUILD SUCCEEDED), and the personal team project
(`MATCHA_PERSONAL_TEAM=YES xcodegen`, with its own app entitlements) builds the same way in Release and in Debug

team (it needs your Apple ID in Xcode), provisioning of the app group and keychain group for the two extensions, and a run
